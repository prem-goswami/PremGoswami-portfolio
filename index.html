01 AI Agents / Security

SQL Agent

Problem
Most text-to-SQL demos hand an LLM a database connection and hope. But the model's output is attacker-influenceable through the user's question, and prompt injection cannot be fixed at the prompt layer, because that layer is exactly what's compromised.
What I built
A natural-language querying agent (FastAPI, GPT-4o-mini, PostgreSQL) with defense in five independent layers: a deterministic sqlparse validator that enforces exactly one statement and SELECT-only over parsed token types, a read-only role with SELECT grants alone, session-level read-only, a 10s statement timeout, and tamper-isolated audit logging the agent role cannot touch.
Outcome
Validated by an 18-case test suite. It kills stacked queries (SELECT …; DROP TABLE …;) while correctly passing WHERE name = 'DROP TABLE', because parsing beats blacklisting. Every response returns the generated SQL, since an agent that returns only prose is unverifiable.

02 AI Agents / Orchestration

Multi-Source Research Agent

Problem
Research agents that retrieve once and generate will confidently answer from insufficient evidence. Someone has to judge whether the sources actually answer the question.
What I built
A 6-node LangGraph agent fanning out concurrent web and RAG retrieval, then fusing both result sets. A critic node judges evidence sufficiency, names the specific gap, and feeds it back into retrieval on a bounded two-correction budget. Exhausting that budget degrades the answer rather than throwing. The model writes the prose; code asserts the source lists and confidence from graph state.
Outcome
Reciprocal Rank Fusion cut a whole class of question from three corrections to one, a 26% latency reduction versus 15% from parallelism alone. The lesson: fixing why work repeats beats parallelizing the repeated work.

03 AI / Retrieval

Advanced RAG & Semantic Search Pipeline

Problem
Standard RAG is embed, cosine search, then stuff into an LLM. That misses exact-term matches like product names and IDs, and produces citations the system cannot actually verify.
What I built
A document Q&A API pairing pgvector dense search with BM25 keyword search, fused via Reciprocal Rank Fusion, then cross-encoder reranking in a two-stage funnel. Parent-child chunking retrieves on precise small chunks but generates on larger parent context, decoupling retrieval accuracy from answer completeness. Citations derive from real chunk metadata, returned as a machine-verifiable sources array.
Outcome
Measured at ~2.6s median retrieval and ~$0.0002 per query (roughly 5,000 queries per dollar) with per-query cost telemetry. Production-hardened: VPC-isolated on AWS ECS Fargate + RDS, per-IP rate limiting, layered prompt-injection defense, async ingestion with job tracking, and token-level streaming.

05 AI / Product Engineering

DSA Student Buddy

Problem
Ask an LLM for help on a LeetCode problem and it hands you the solution, which is precisely what a learner must not receive. The hard part isn't calling the model; it's stopping it from answering.
What I built
A Manifest V3 Chrome extension with clean runtime boundaries: a content script extracting on-page problem context, a background service worker orchestrating the Gemini API, and a React options page for configuration. Behavioral guardrails and structured response contracts prevent full-solution leakage, with client-side normalization recovering from malformed model output.
Outcome
Reliability engineered for real LLM APIs: dynamic model discovery via ListModels with candidate routing and persistence instead of assuming one model stays callable, retry-aware handling of 400/404/429/503, and a graceful degraded path during rate limits. Progressive hints encode pedagogical intent rather than answer dumping.

06 AI / Automation

Integrated LLM Workflow Service

Problem
Tracking job applications means constantly reopening a spreadsheet, and the managed automation platforms that could fix it all carry a subscription.
What I built
A conversational tracker run entirely over WhatsApp: an 8-node n8n workflow wiring the WhatsApp Cloud API to Google Gemini with a buffer-window memory node for multi-turn state, and Google Sheets as the database. Log an application, update its status, or query by status in plain language, and every change lands in the sheet instantly.
Outcome
Zero recurring cost: self-hosted n8n in Docker with an ngrok tunnel serving the webhook, replacing a paid cloud subscription. Stateful conversation, auto-generated application IDs, and no new app to install, because the interface is a chat the user already has open.
